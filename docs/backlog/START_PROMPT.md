# Промпт для начала работы в новой сессии

> Скопируй текст ниже (начиная с `---`) и вставь первым сообщением в новую сессию ZCode.
> Это даст агенту контекст, куда смотреть и что делать.

---

Прочитай и строго соблюдай `AGENTS.md` в корне репозитория — это инструкция по архитектуре,
IPC-контракту, конвенциям кода и дизайн-системе (опора на DESIGN.md).

Контекст: есть бэклог задач по итогам анализа проекта.

1. Открой `docs/backlog/CHECKLIST.md` — это единый чек-лист. Там описаны правила:
   задачи брать по приоритету (P0 → P1), а когда задача готова — отметить пункт `[x]`, дописать
   дату/коммит в журнал и **удалить файл задачи** из `docs/backlog/`.
2. Открой `docs/report/2026-06-20-analysis.md` — там подробный отчёт с обоснованием каждой задачи.
3. Выбери **первую невыполненную** задачу из чек-листа, открой её файл в `docs/backlog/`
   (`<ID>-<slug>.md`), изучи разделы «Проблема / Цель / Что сделать / Где менять / Чек-лист».

Начни с задачи: **укажи ID здесь** (например `P0-04`). Если ID не указан — начни с первой
невыполненной P0.

Что от тебя требуется по этой задаче:
- Реализуй изменения строго по «Что сделать», держи контракт IPC `{ ok, ... }` и не ломай правила
  из AGENTS.md (русские комментарии, CommonJS, `'use strict'`, дизайн-токены из DESIGN.md).
- Не добавляй новые runtime-зависимости без причины.
- Проверь свой «Чек-лист выполнения» из файла задачи: `npm start` / `ZS_DEBUG=1 npx electron .`
  открывают окно без ошибок, при необходимости `npm run dist:dmg`.
- Когда закончишь:
  1. в `docs/backlog/CHECKLIST.md` отметь пункт `[x]`;
  2. в раздел «Журнал выполненных задач» добавь строку
     `✅ <ID> — <описание> — <дата> — <commit>`;
  3. **удали файл задачи** из `docs/backlog/`.
- Закоммить изменения (в отдельную ветку, не в `main` напрямую) и создай PR, если пользователь
  попросил заливать в git.

Перед началом — кратко перескажи план по выбранной задаче и согласуй, если есть варианты решения.
